# 🔐 Секретка — шифрованный мессенджер

Мессенджер в браузере со сквозным шифрованием (E2E). Ключи и расшифровка живут **только на устройствах собеседников**: сервер хранит лишь шифротекст и не может прочитать ни одного сообщения.

## Возможности

- **Шифрование E2E** — X25519 (обмен ключами) + AES-GCM (шифрование сообщений), Web Crypto API. Ключ каждого сообщения уникален (случайные salt + IV).
- **Система друзей** — поиск по имени, заявки, принятие/отклонение, удаление из друзей.
- **Живой обмен** — WebSocket: доставка сообщений в реальном времени, статус «онлайн», индикатор «печатает…».
- **История** — сообщения хранятся на сервере только в зашифрованном виде.
- **Бэкап ключа** — секретный ключ можно скопировать и восстановить на другом устройстве.
- **Темы** — «Неон» (бирюза, по умолчанию), «Нуаръ» (чёрный + багровый), светлая, сиреневая. Переключаются на лету и запоминаются.
- **Медиа** — фото, видео, музыка и любые файлы до 15 МБ; шифруются на устройстве до отправки.
- **Видеокружки** — зажал кнопку камеры, записал, отпустил — улетело. Собеседник видит круглое видео.
- **Адаптив** — телефон, планшет, ноутбук: на узких экранах список чатов превращается в шторку, модалки — в bottom-sheet.
- **Живые заявки и диалоги** — новые заявки, принятие и сообщения прилетают по WebSocket без перезагрузки.
- **Демо-режим** — `?demo=demo_alice` или `?demo=demo_bob` (пароль `demo`) создаёт двух демо-пользователей с перепиской для знакомства с интерфейсом.

## Быстрый старт (ноутбук / ПК)

Требуется Node.js 18+.

```bash
npm install
npm start
```

Открой **http://127.0.0.1:8080** — зарегистрируйся, создай ключ (сохрани бэкап!), добавь друга по имени.

Чтобы девушка могла писать с телефона/ноутбука в той же Wi-Fi сети — открой **http://<твой-LAN-IP>:8080** (сервер сам напечатает адреса при запуске). Мобильная вёрстка адаптивная.

### Демо

```bash
npm run demo    # Windows: DEMO=1 + node server.js
# затем открой http://127.0.0.1:8080/?demo=demo_alice
```

## Публичный доступ (когда собеседник не рядом)

Два бесплатных варианта:

1. **Cloudflare Quick Tunnel** — если сервер запущен на ноуте:
   ```powershell
   tools\cloudflared.exe tunnel --url http://127.0.0.1:8080 --no-autoupdate --edge-ip-version 4
   ```
   В логе появится адрес вида `https://<случайные-слова>.trycloudflare.com`. Он живёт, пока включён ноут и запущен туннель; после перезапуска туннеля адрес меняется.
2. **Render (постоянный адрес)** — пошагово в [RENDER.md](RENDER.md), конфиг уже готов в `render.yaml`. На бесплатном плане сервис засыпает после ~15 минут простоя и хранит данные эфемерно (после деплоя история обнуляется).

## Криптография

| Слой | Механизм |
|---|---|
| Ключи пользователя | X25519 (TweetNaCl `box`), генерируются в браузере |
| Общий секрет диалога | `X25519(секретный_ключ_A, публичный_ключ_B)` — сервер его не знает |
| Шифрование сообщения | AES-GCM-256, ключ = `SHA-256(общий_секрет ‖ salt)`, salt и IV случайные на каждое сообщение |
| Аутентификация | AES-GCM с AAD = ключ диалога (искажённое сообщение молча отбрасывается) |

**Что может сервер:** видеть метаданные (кто кому пишет, время, размер), но не содержимое. Онлайн-статус и заявки — служебные и не шифруются.

**Ограничения (честно):**
- Ключ диалога статический (простой ECDH), поэтому строгой forward secrecy (как в Signal) нет. Если у злоумышленника будет и общий секрет, и вся история — он её расшифрует.
- Приложение не защищает от компрометации самого устройства (кейлоггер, скриншоты, malware).
- Токены и пароли хранятся/проверяются сервером (scrypt + SHA-256 токенов).

## Структура

```
public/index.html      — страница
public/app.js          — клиент: UI, друзья, WebSocket, криптография
public/js/crypto.js    — крипто-ядро (работает и в Node — тестируется)
public/styles.css      — темы (Неон / Нуаръ / светлая / сиреневая) и адаптив
public/vendor/         — TweetNaCl (единственная клиентская зависимость)
lib/store.js           — хранилище (JSON-файл, атомарная запись)
server.js              — HTTP-API + WebSocket, статика, приём медиа
test/crypto.test.js    — тесты криптографии
test/e2e-media.js      — сквозной прогон API (дружба, медиа, права доступа)
scripts/ws-test.js     — тест live-доставки по WebSocket
scripts/probe.js       — headless-проба интерфейса через CDP (метрики раскладки)
scripts/probes/        — сами проверки: layout.js (раскладка, скролл), auth.js (вход)
render.yaml            — конфиг для Render (Blueprint)
RENDER.md              — деплой на Render по шагам
Dockerfile             — образ для VPS
```

## API (кратко)

`POST /api/register`, `POST /api/login` → токен · `PUT /api/me` (публичный ключ) · `GET /api/friends` · `POST /api/friend/request|accept|decline|remove` · `GET /api/friend/requests` · `POST /api/msg` (шифротекст) · `GET /api/conv/<nick>?after=` · `POST /api/seen` · `WS /ws?token=`

## Тесты

```bash
npm run test:crypto   # roundtrip, неверный AAD, порча шифротекста, экспорт/импорт ключа
node scripts/ws-test.js  # доставка сообщения по WS при живом соединении + presence
node scripts/probe.js --url http://127.0.0.1:8080/ --w 1440 --h 900 --eval scripts/probes/layout.js
```

## Лимиты

Сообщение ≤ 40 000 символов шифротекста, до 1000 сообщений на диалог в хранилище, имя — 2–20 символов (буквы/цифры/`_`), пароль 4–72 символа.
